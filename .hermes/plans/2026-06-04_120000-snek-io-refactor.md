# snek-io refactor + perf fix

**Project:** /home/rrich/money_makers/snek-io
**Stack:** Vite + TypeScript client (WebGPU), SpacetimeDB 2.0 TypeScript module
**Goal:** Stop the slowdown as the player's snake grows + tidy up the rushed code.

## Phase 1 — Performance fixes (no behavior change)

### 1.1 Server: per-tick segment cache
**File:** `spacetimedb/src/index.ts`
- At the top of the tick reducer, build `playerSegments: Map<IdentityString, SnakeSegment[]>` and `botSegments: Map<bigint, SnakeSegment[]>` ONCE by iterating the tables a single time.
- Replace every `getSegmentsByOwner(ctx, id)` / `getBotSegments(ctx, id)` call inside the tick with a Map lookup.
- Keep the original helpers for use outside the tick (e.g. in `join_game` / `leave_game`).
- This is the dominant cause of the slowdown. With N snakes of length L, the tick goes from O(N²·L²) array materializations to O(N·L) for the build + O(1) lookups.

### 1.2 Client: persistent name labels
**File:** `client/src/main.ts` (later `client/src/ui.ts`)
- Maintain a `Map<identity, HTMLDivElement>` of pre-created label divs.
- On each frame, iterate the map: update `textContent`/`style.left`/`style.top`, or set `style.display = 'none'` if off-screen.
- No more `innerHTML = ''` and no more per-frame `<div>` creation.
- Bonus: when a snake dies, remove its label from the map.

### 1.3 Client: reusable vertex buffer
**File:** `client/src/main.ts` (later `client/src/renderer.ts`)
- Pre-allocate one `Float32Array` sized to `maxVertices * 5`.
- Use a write cursor (integer index into the array) instead of `vertices.push()`.
- Reset the cursor at the start of each `render()` call.
- Skip the per-frame `new Float32Array(vertices)` copy.
- `writeBuffer` with a `size` argument that's exactly the used portion (avoid uploading zeros for unused tail).

### 1.4 Client: keep segments sorted on insert
**Files:** `client/src/main.ts` setupCallbacks
- In `snake_segment.onInsert` and `bot_segment.onInsert`, insert in the correct sorted position (binary search by segmentIndex) instead of pushing to the end and re-sorting every frame.
- Drop the per-frame `[...segs].sort()` in `gameLoop`.

### 1.5 Client: viewport culling
**File:** `client/src/main.ts` (later `client/src/renderer.ts`)
- Before rendering a snake, do a coarse AABB test: skip it entirely if none of its segments could overlap the viewport + a small margin.
- This is the actual cause of the player-length-correlated slowdown in the renderer — a long snake has many body segments, and we currently render all of them every frame.

## Phase 2 — Server module tidy

### 2.1 Extract `killSnake` helper
**File:** `spacetimedb/src/index.ts`
- Replace the 5 copies of the "set alive=false, emit died event, drop food from segments, delete segments" sequence with a single helper that takes a target and a segments-list.
- This collapses ~150 lines into ~30.

### 2.2 Extract `moveSnake` helper
**File:** `spacetimedb/src/index.ts`
- Player and bot tick branches are 90% identical. Extract the shared work: clamp direction, compute new position, eat food, move segments, grow on eat, check collisions (all using the per-tick segment cache from 1.1).
- Branch-specific bits (the dash decision, the death-event table) become small post-calls.

### 2.3 Drop redundant `[...ctx.db.X.iter()]` materializations
**File:** `spacetimedb/src/index.ts`
- `for (const x of ctx.db.X)` is fine — iterators are iterable. SpacetimeDB's `iter()` returns an iterator, no need to spread it.

### 2.4 Simplify `on_disconnect`
**File:** `spacetimedb/src/index.ts`
- The "clear everything and respawn food and bots" block is unnecessary. Dead-player/bot cleanup already happens in the tick. The only thing `on_disconnect` needs to do is: delete the disconnecting player's segments and row, then check if the game should pause/resume.

## Phase 3 — Client module split

### 3.1 New file layout under `client/src/`
- `config.ts` — COLORS, MAP_SIZE, SERVER, DB_NAME, sound URLs
- `sound.ts` — SoundManager (moved out of main.ts)
- `renderer.ts` — WebGPURenderer (moved out of main.ts, with the perf improvements from 1.3 and 1.5)
- `input.ts` — keyboard/mouse/touch state machine → `getDirectionAngle()` + dash triggers
- `ui.ts` — menu, leaderboard, name labels (with the persistent-div optimization from 1.2)
- `game.ts` — Game class: SpacetimeDB connection, callbacks, game loop, leaderboard refresh
- `main.ts` — bootstrap only: load, instantiate Game, start

### 3.2 Remove dead code
- Drop the `iMobile` typo, the unused MutationObserver in PWA install, the dead `try/catch` around `getCameraPosition` (it can never throw on a renderer that's been constructed), and the `validKeys` array that's checked twice (once against `e.key`, once against `e.code` — only `e.code` is reliable).

## Validation
- `cd client && npx tsc --noEmit` must pass.
- `cd spacetimedb && npx tsc --noEmit` must pass (or `npm run build` if there is no separate check).
- `cd client && npm run build` must succeed.
- No `spacetime publish` is needed — code is verified locally. The user publishes when ready.

## Risks
- Behavior of collisions must stay identical. The cache from 1.1 is built BEFORE any segment updates in the tick, so it captures the start-of-tick state — same as the original `getSegmentsByOwner` calls. The collision-during-movement uses the in-progress `newSegmentPositions` array (unchanged).
- WebGPU shader/bind-group layout is identical. Vertex layout (5 floats per vertex) is unchanged. The renderer just doesn't allocate fresh typed arrays each frame.
